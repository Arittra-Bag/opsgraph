# OpsGraph investigation UI

Build-free browser interface served by the existing OpsGraph backend. The
canonical assets live in `src/opsgraph/web`; this directory is a byte-identical
preview mirror. Keep both copies synchronized when editing.

## Run

Use the repository's native installation instructions, then run `opsgraph serve`
and open the reported local address. The backend serves `index.html` from `/`
and assets from `/assets/static/`. Opening the HTML directly or serving this
folder alone does not provide the authenticated API or correct asset mount.

The initial page contains no investigation results. Connect with the workspace
key generated by `opsgraph init`, configure an approved read-only PostgreSQL
source, inspect its explicit table scope, and test an actual model connection.
Model unavailability does not block source setup or viewing saved investigations.
Source connection URLs and model credentials belong on the backend host; the
browser accepts only approved source environment-variable references.

## Behavior

- `POST /api/runs` returns a persisted run. Progress comes from authenticated SSE
  over `fetch`, with the workspace key in a header, never a URL.
- Reconnect resumes recorded events for the existing run without submitting again.
  Network disconnection and backend run state are displayed separately.
- Cancellation waits for backend confirmation. Interrupted runs require explicit
  retry as a new attempt. Follow-ups retain the preceding turn and its evidence.
- Claim references open matching captures, exact SQL, source identity, timestamps,
  effective query limits and truncation. Model classification and evidence hashes
  do not establish semantic support or causality.
- Export downloads the full saved investigation. No sample replay, prewritten
  conclusion, invented source status or timed execution animation is used.
- The existing custom playbook JSON draft/publish workflow remains under Advanced.

## Accessibility and verification

The UI includes semantic controls, visible keyboard focus, modal background
isolation, Escape/focus return, reduced motion, responsive layouts and scrollable
evidence tables. These implementation choices require browser validation; they
are not an accessibility certification.

Run focused checks:

```sh
node --check src/opsgraph/web/static/app.js
node --test tests/frontend/events.test.cjs
python -m pytest tests/unit/test_web_mirror.py
```

Node is needed only for these optional developer checks, not for installation or
running the browser UI. SSE fixture tests cover framing, ordering, disconnects and
UTF-8; they do not replace real PostgreSQL/model or cross-platform acceptance.
